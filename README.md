## 快速开始

去 [Releases](https://github.com/aicbbuu/aicbbuu-network-tools/releases) 挑一个包：

| 包 | 适合谁 |
|---|---|
| `aicbbuu-network-tools-<版本>-win-x64.exe` | 想直接双击就跑、不在系统里留东西（U 盘、公司电脑、先试用） |
| `aicbbuu-network-tools-Setup-<版本>-win-x64.exe` | 想装到开始菜单和桌面、能从「应用和功能」里正常卸载 |

**两个包内容完全一样**，只是后者多了快捷方式、卸载项和开机自启选项
（安装时勾）。**都不需要安装任何东西** —— Python、Qt、网络工具全都在
包里了。

- Windows 10 / Windows 11（x86_64）
- 体积约 47 MB（免安装）/ 49 MB（安装包）

## 功能

侧边栏第一项是**故障诊断** —— 你只需要描述症状（「网页打不开」），
它自己逐层查完给你结论，而不是让你先想清楚该测什么。
第二项**网络修复**是可以展开的二级菜单，8 项操作按**风险从低到高**
排列，从上往下试就行。其余是单项工具，按网络栈从外到内排列。

| 页面 | 用途 |
|------|------|
| **故障诊断** | 只给一句「网页打不开」时用这个。按协议栈逐层探测，输出**结论 + 证据链 + 建议动作** |
| **网络修复**（二级菜单） | 8 项操作各占一页，点开菜单选一项即可：**清空 DNS 缓存 / 查看 Winsock 目录 / 查看当前 IP 配置 / 重新获取 IP 地址 / 重置 WinHTTP 代理 / 释放 IP 地址 / 重置 TCP/IP 协议栈 / 重置 Winsock 目录**。每页都常驻显示这一项做什么、会有什么影响、将要执行的命令原文；执行前自动备份配置，危险操作二次确认且默认焦点在「取消」 |
| **延迟测试** | ICMP 延迟与丢包率，含最短/平均/最长/抖动 |
| **HTTP 检测** | 分层验证能不能上网：DNS 解析 → TCP 连接 → TLS/HTTP，三层分别计时 |
| **路径 MTU** | 设 DF 位二分探测不分片包的上限，定位 VPN/隧道导致的 MTU 黑洞 |
| **MTU 逐跳** | 追踪路径后对**每一跳**做 MTU 二分，找出是哪一段链路压低了 MTU，并告诉你该找谁修 |
| **多目标对比** | 一次并发测多个目标。价值在**对比**：个别不通是目标自己，全不通才是本地问题 |
| **路由追踪** | 逐跳显示数据包经过的路由器，定位断点 |
| **DNS 解析** | 域名解析结果 + 本机解析耗时 |
| **端口检测** | TCP 连接探测，19 个常用端口或自定义范围 |
| **带宽测速** | 下载测速。**测速时长可自选**（5 / 10 / 15 / 30 / 60 秒，默认 10 秒），测速源也可手动选择，默认「自动」按顺序降级 |
| **WiFi 无线** | 两个子页：**当前连接**（信号强度、频段、信道、协商速率、五档评价）与**网络扫描**（扫描周围所有可见 AP，按 6/5/2.4GHz 分组列出 SSID、BSSID、频段、信道、信号、加密、速率，并标出未加密的开放网络） |
| **局域网** | 默认网关、DHCP 服务器、ARP 邻居表，并实测网关连通性 |
| **TCP 握手** | 把建连耗时拆开，区分「延迟高」与「握手丢包重传」 |
| **ARP 列表** | 本机直连网段的邻居表（IP ↔ MAC），排查 IP 冲突与蹭网设备 |
| **子网扫描** | 扫描整个网段的 IP 占用情况。ARP / TCP / ICMP 三层交叉取证 |
| **系统网络状态** | 路由表、DNS 缓存、TCP 全局参数、网卡与 MTU、防火墙、Winsock 目录、协议统计。只读 |
| **网络信息** | 本机网卡、IP、DNS、代理与当前 TCP 连接 |
| **IP 工具** | 三个纯计算子工具：IPv4 子网计算器、地址转换器、范围转 CIDR |
| **关于** | 版本、许可协议、源码仓库地址 |

「IP 工具」不发起任何网络请求，全部是位运算，可以放心离线用。

默认浅色主题。标题栏右上角（最小化按钮左边）有一个主题切换按钮，
点一下在浅色 / 深色之间切换，图标会跟着变（月牙 → 太阳）。

标题栏左侧软件名后面常驻显示版本号（如 `v1.0.0`）。这是给报 bug 时用的
—— 窗口是无边框的，任务管理器里显示的窗口标题看不到版本号，截个图就能
对上你装的是哪一版。

**硬件限制**：WiFi 的两个子页都需要无线网卡。用网线连接、或本身没有
WiFi 硬件的机器（多数服务器、虚拟机）会提示「WLAN 服务未运行」——
这是硬件限制，不是程序问题。

各页的目标地址默认填 `localhost`（端口检测是 `127.0.0.1`）——
测本机不花钱也不占公网带宽。**路由追踪和路径 MTU 例外**：这两项
打 `localhost` 分别只会 1 跳就结束、永远返回 1500，测不出任何东西，
所以默认填的是外网地址。

### 为什么要有「HTTP 检测」

ping 通不等于能上网。最常见的三种「ping 得通但网页打不开」分别是
DNS 污染、TCP 端口被阻断、TLS 握手被劫持——**这三种在 ping 看来
完全一样**。HTTP 检测把三层拆开单独计时，出问题时直接告诉你卡在哪一层。

### 为什么要有「故障诊断」

其余页面是工具箱——你得先知道要测什么才去点。但真实的网络故障是
「网页打不开」，**没人知道问题在哪一层**。

这一页按网络协议栈从底向上逐层探测，每层的结果决定要不要继续往下，
输出的是**结论和证据链**，不是一堆数据：

    ✓ 本机配置      正常    网卡、MTU、DNS 配置正常
    ✓ 网关连通      正常    192.168.1.1 可达（2 次往返 3 ms）
    ✓ 公网连通      正常    8.8.8.8 可达（2 次往返 18 ms）
    ✓ DNS 解析      正常    example.com → 93.184.x.x（14 ms）
    ✗ HTTPS 请求    异常    TLS 握手超时

判断规则是**第一个异常层就是根本原因**——后面的层失败只是它的表现。
上面这个结果会直接告诉你「DNS 没问题，是 TLS 握手被干扰」，并给出
排查方向（系统时间、企业 HTTPS 审计代理等）。反过来，如果网关就
不通，后面的层会标记为「未执行」而不是「异常」，避免给你一个
「DNS 坏了」的误导结论。

### 为什么「网络修复」要做成二级菜单

它是唯一一组会修改系统设置的操作，收在单独的一级菜单里，
一眼就能看出「这些东西点了是有后果的」。菜单里的 8 项按
**风险从低到高**排列：只读的查看类在最前，然后是「清 DNS 缓存」
（不影响网络），再是会短暂断网的续租 IP，最后是必须重启的
重置 Winsock。**遇到问题请从上面开始试**，不要直接跳到重置。

**一项一页**，不挤在一个页面里。这样每一页都能把话说完：
做什么、会有什么影响、会不会断网、要不要重启、将要执行的
命令原文，全部常驻显示，不用点下去才知道，也不用鼠标悬停
才看得到。

菜单里的按钮按风险着色：**蓝色是低风险**（只读或不影响网络）、**橙色是中风险**
（会短暂断网）、**红色是高风险**（需要重启才能恢复）。不用读文字也能一眼
分出哪些要谨慎。

三项防护：

- **后果说明与命令原文常驻可见** —— 就在页面上，不是点下去才知道
- **二次确认** —— 会修改设置的操作弹窗列出完整命令原文，
  让你能自己判断，而不是只能点「同意」；默认焦点在「取消」
- **执行前自动备份** —— 把网卡 MTU、完整 IP 配置、路由表存到临时文件，
  出问题可以照着改回来

关于管理员权限：需要提权的操作会调 Windows 自己的 UAC 对话框，
**这个弹窗只能由你本人点击**——程序既读不到也代替不了你的选择，
这是 Windows 的安全设计。

### 为什么要有「子网扫描」

**「ping 通」不等于「有人在用」**，反过来也一样。四种常见情况都会骗人：

- 设备待机 → ping 通，但没人用（IP 仍被占着）
- Windows 防火墙拦截入站 ICMP → **ping 不通，但确实有人在用**
- Linux / 网络设备 → 默认禁 ping，但有人在用
- DHCP 刚续约 → ping 不通，但地址已被保留

所以这一页分三层取证，各管一段：

| 判定 | 依据 | 可信度 |
|------|------|--------|
| ● 确定在用 | ARP 表 | 设备必须回 ARP 才能通信，**无误判** |
| ◆ 高概率在用 | TCP 端口（445/3389/22…） | 445 开着基本确定是 Windows 设备 |
| ◐ 响应 ICMP | ping | **最弱** —— 防火墙会骗人 |
| ○ 无响应 | — | 明确标注「**这不等于空闲**」 |

最后那句话是关键：给已被占用的地址分配新设备会造成 IP 冲突，
这是「凭 ping 判断」最常见的踩坑方式。

扫描范围限定在你填的网段内（最多 2000 个地址），只发本机直连子网的
流量，不扫描公网。

### 为什么要有「路径 MTU」

挂 VPN / PPPoE / 隧道时路径 MTU 常被压低（1500 → 1400），小包正常而
大包被静默丢弃。症状是 **ping 完全正常、网页也能开，但加载很慢、
传大文件卡死**。ping 只发小包，永远测不出这个问题。

判定阈值按实际存在的标准 MTU：1500（以太网）、1492（PPPoE 标准值，
属正常）、1400（常见 VPN）、1280（IPv6 最小）。

界面为中文，支持深色 / 浅色主题。


## 已知限制

**ping 全超时 ≠ 网络故障。** 很多企业网络、VPN、容器网络会在协议层拦截
ICMP。能正常浏览网页就说明网络是通的，工具会提示这一点。

**带宽测速需要外网。** 测速用的是公共 CDN。如果 DNS 被劫持或这些源被限制
访问，测速会失败并提示原因。

**测速时长越长越准。** 默认 10 秒。极短时间（比如 2 秒）里握手和首字节的
开销占比很大，会把结果压低；60 秒则更稳，但要占用一分钟带宽。测速结果按
实际下载量和实际用时计算，而不是按固定大小。

## 数字签名

Release 里的 exe 用**自签证书**签名，所以：

- 文件确实带数字签名，完整性和来源可校验
- 但 Windows 仍会显示**「未知发布者」**——自签证书不在系统的受信任
  根列表里，这是必然的，不是 bug

想让它变成「已验证的发布者」，需要将签名者证书导入 Windows 的
「受信任的根证书颁发机构」，或者改用 OV 证书（SignTool 会自动把签名
加入 Windows 的信任列表，双击即显示为已验证的发布者）。

签名带 DigiCert 时间戳，证书到期后签名依然有效。

> ⚠️ 杀毒软件的误报提示与签名无关。PyInstaller 打包的程序会先把自己
> 解压到临时目录再运行，行为特征接近常见木马，未签名的自打包 exe
> 被误报是普遍现象。校验文件请用 Release 里的 `SHA256SUMS.txt`。
